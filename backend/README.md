# Lira chat backend

Tiny FastAPI service that powers the "Лира" chat in the Lira web app.

## What it does

Exposes the contract that the bundled chat UI already speaks:

- `GET /v1/lira/status` → `{"enabled": true, "model": "openai"}`
- `POST /v1/lira/chat` → `{"reply": "..."}`

Internally it forwards messages to [Pollinations.ai](https://pollinations.ai)'s
free, no-API-key, OpenAI-compatible chat endpoint. We wrap each request with
a Russian-language "warm cycle confidante" system prompt that includes the
user's `cycle_day` and `phase`, so Лира stays in character across sessions.

## Why Pollinations.ai

- **Free**, no API key, no signup.
- Reachable from Russia without proxies.
- OpenAI-compatible request/response shape.

If Pollinations is overloaded (HTTP 5xx) we retry with jittered backoff. If
all retries fail we return a soft, on-brand canned reply rather than a 502 —
the chat is the headline feature of the app and we never want it to surface
a raw error.

## Deploy

```bash
fly deploy --remote-only
```

The repo's `fly.toml` is auto-generated by the platform deploy tool; the
production app is deployed at `https://lira-backend-leoiurwi.fly.dev/`.

## Local dev

```bash
cd backend
uv sync
uv run fastapi dev app/main.py
```

The frontend (in `dist/index.html`) is patched at export time by
[`scripts/postexport-web.mjs`](../scripts/postexport-web.mjs) — it injects a
small `window.fetch` interceptor that rewrites any request whose path is
`/v1/lira/{status,chat}` to the deployed backend. To point the web app at a
local backend instead, edit the `BACKEND` constant in
[`scripts/lira-webllm-inject.html`](../scripts/lira-webllm-inject.html).

## Environment variables

- `POLLINATIONS_URL` — chat completion endpoint (default `https://text.pollinations.ai/openai`).
- `POLLINATIONS_MODEL` — model name on Pollinations (default `openai`, which
  resolves to `openai-fast` / GPT-OSS 20B on the anonymous tier).
- `POLLINATIONS_RETRIES` — retry attempts on 5xx (default `3`).
